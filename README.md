# Session Context Debugger

A local browser app for inspecting recorded Codex/T3 Code and Claude Code sessions, including Desktop Code and SDK origins.

The source picker defaults to T3 Code, with Claude and Codex recording views available. Select a T3 thread to inspect its recorded current provider binding and open a recording with a corroborated provider ID. You can also open a local JSONL path or a stat-only recent-file candidate. The Beginning view separates submitted/human-recorded input from captured setup, shows first-response usage, and links evidence to hash-validated source ranges. A physical-line ledger preserves metadata, unknown shapes, malformed data, pending tails, and normalization limits.

Recorded content, diagnostic snapshots, request inclusion, and active-context evidence retain separate meanings. A prompt snapshot is diagnostic evidence; it does not add another injection. Provider usage is reconciled by actor-scoped recorded identity, with conflicts excluded from resolved totals. Payload bytes do not claim exact token attribution.

## Explore a recording

- Selecting a recording hides the session picker. Use **Select session** in the header to reopen it.
- Input, output, cache-read, and cache-creation subtotals stay above the timeline. Each metric shows measurement coverage; unknown fields stay unknown. These are cumulative provider-reported usage in the selected recording, not current context size, billing, or complete T3 history.
- **Visual timeline** shows recorded ranges, event markers, and one selected event. Click a colored type to show only that category. Click it again or **All activity** to clear the filter. The dropdown uses the same selection and also offers combined tool calls/results. Filtering preserves original positions; spacing describes recorded order, not elapsed time or tokens.
- Tool counterpart links use recorded IDs within an actor. Jumping to the opposite event clears a blocking activity filter and selects the exact retained event. Ambiguous/orphan pairings and coverage limits remain explicit.
- Selected Codex events link lifecycle and `response_item` representations only through recorded `item.id` within the source actor/thread. Each content block stays separate; the link does not prove identical content, another execution, request membership, or active inclusion. Claude `toolUseResult` runtime metadata links to same-record `tool_result` content only through a matching recorded `tool_use_id` or a unique retained result block. Multiple candidates remain ambiguous with no guessed target. Both representations retain independent source inspection, and relationship links include their basis, exact target, and indexing coverage.
- **Category ranking** compares compact JSON UTF-8 bytes of captured fields or event counts, with separate evidence views and source links. It covers the whole retained index independently of the timeline filter. Nested captures share byte allocation within one record; copies in other records remain separate. Shares cover measured bytes only. These sizes are not raw log storage, category token counts, or proof of active context.
- Open **Usage and input-token ranking** below the recording view for source-linked responses, sorted by input tokens by default or by source order. Sorting covers the retained response set before paging. Unknown/conflicting input measurements stay unranked. Closing and reopening preserves order and page; a new recording starts with the panel closed.
- Open **Cumulative recorded usage** beside the provider-input chart to follow input, output, cache-read, or cache-creation subtotals across the retained source-ordered response groups. It pages at most 200 groups while carrying the prefix across pages and compaction markers; it retains at most 20,000 groups. Each field shows its eligible measurement count, included and excluded groups, and latest eligible source reference. Missing, conflicting, unsupported, and overflow rows remain selectable gaps and break the plotted segment; recorded zero remains a measurement. These are derived partial known subtotals, not source-native accumulated measurements, billing, wall-clock history, or active-context size. Cache read is not added again to input; reasoning remains a subcomponent of output. Runtime counters stay separate.
- **Show in timeline** jumps from a usage row to recorded response content when linked through matching usage records, or to its usage event when response-content association is unknown. It clears blocking filters and shows the selected observation's input/output/cache fields and bounded recorded links. Nearby prompts and instructions are surrounding activity, not proven request contents. Missing timeline targets remain unavailable within retained coverage.
- **Beginning and instructions** retains first-input and captured startup evidence. **Inspect source** opens hash-validated raw records or selected fields in bounded ranges.
- **Search this recording** finds case-sensitive literal text in the selected raw UTF-8 JSONL snapshot, including oversized and unknown records. JSON escapes stay escaped. Search is independent of activity filters, keeps one first-match result per line, and stops at 100 matching lines or 30 seconds with explicit incomplete coverage. Cancelled searches never establish absence. Inspect match opens a hash-validated range at its byte offset; the timeline jump selects the first indexed event on that line, which may be a different field. Search reads are bounded and memory-only.
- **Category ranking** and **Search this recording** start collapsed. Open their headers when needed; closing/reopening retains controls and results, and an active search continues with its status visible in the header. Selecting a new recording resets both panels.
- **Coverage notes** appear as a compact count beside the recording information. Open it to read every notice; routine unrecognized formats use a neutral style, while recorded read failures and incomplete scan/normalization conditions use amber. Escape closes the notes, and reopening a recording resets them.
- **Related sessions** connects supported recorded Codex subagent activity and Claude Agent/Task calls to corroborated recordings. Open its collapsed panel or follow a timeline event's **Find child recording** link, inspect the identity/sidecar evidence, then choose a verified target. Missing evidence stays unverified; contradictions disable navigation. Child actor/thread identity and root grouping stay separate, and usage is never added across linked recordings. **Back to parent recording** revalidates and reopens the earlier recording; it does not restore an old index or selection. Discovery limits and unsupported layouts remain explicit.
- **Recorded response** opens within selected assistant/tool/reasoning/usage activity. Provider response groups keep strict identity: Claude assistant blocks require recorded actor/requestId/message.id; Codex provider usage and embedded aliases require response_id within the selected actor/thread. Assistant captures without that full identity can appear in a separate capture-only group: Codex `response_item` assistant messages, reasoning and tool calls, or Claude assistant response blocks are grouped only when they share the same physical source record. Each copy stays independent. These groups do not identify a provider response, request, or model invocation; request and provider-usage association remain unknown, and same-row usage is not assigned as a variant or added to totals. Browse retained groups in first-recorded order, inspect source lines, and see up to 10 usage variants for provider groups and 20 event links for either group, with omissions and coverage. Nearby prompts, snapshots, tool results, counters, and Codex item IDs do not establish request membership.

## Local use

Requires Node 22.12 or later.

T3 catalog reads use Node's built-in experimental SQLite module. The start script enables it on Node 22.12; no external SQLite dependency is installed. [Node's SQLite documentation](https://nodejs.org/download/release/v22.12.0/docs/api/sqlite.html) describes the read-only connection option and flag.

    npm install
    npm run typecheck
    npm run build
    npm start

Open the access link printed by the server. It binds to 127.0.0.1 on an automatically assigned port. The random credential is consumed from the URL fragment, retained only in tab memory, and removed from the address bar. Reloading requires reopening the access link.

Keep the server process running while using the app. When launching it manually, keep its terminal open. If the page reports that it cannot reach the local server, start the app again and open the new access link; an already loaded page cannot read files after its server stops.

    npm start -- --port 8766
    npm start -- --root /absolute/path/to/session-directory

An explicit root replaces the default roots for that launch. Default roots are .codex/sessions, .codex/archived_sessions, and .claude/projects under the current user's home. Realpath containment applies, including junctions/symlinks. Source files are read-only. No source content, index, or body cache is persisted by the app or sent to remote services.

The T3 catalog source is the current user's .t3/userdata/statev2.sqlite. Each operation opens a read-only connection with query_only enabled, validates the required schema, reads a short transaction, and closes it. Listing reads orchestration_v2_projection_threads and projection_projects; current provider identity follows active_provider_thread_id through orchestration_v2_projection_provider_threads and a matching (provider_session_id, thread_id) row in orchestration_v2_projection_provider_session_bindings. Provider-session metadata is optional. Provider-thread evidence includes required metadata and only the bounded payload_json.nativeThreadRef.nativeId leaf; the full provider-state payload is not exposed. An absent, busy, or unsupported catalog produces a visible error; Claude/Codex selection and explicit paths remain available.

T3 catalog projections and provider JSONL records retain separate evidence references. Inspect catalog evidence revalidates the full captured row projection and reports changes without substituting current values; Inspect log identity opens the corroborating JSONL field. Opening a linked recording revalidates the thread identity, active provider-thread reference, provider instance, and deletion state, plus the provider-thread/native-ID and session-binding projections around JSONL identity validation. Display-only thread changes do not invalidate an established link. A projection hash does not hash the entire database or unlisted row fields.

## Current scope and limits

Beginning and T3 discovery are implemented with scoped verification. Conversation/tool browsing, clickable visual navigation, literal raw-source search, supported parent/child and recorded-response navigation, bounded Codex item and Claude runtime-result relationships, usage subtotals/ranking, captured payload ranking, the provider-input chart with source-linked compaction markers, cumulative recorded usage, and bounded recorded context-window intervals are usable increments. The broader milestones remain in progress: other relationship/mirror coverage, fuller context-window reconstruction, runtime-counter and byte charts, duplication/exposure diagnostics, and enriched discovery/refresh are still pending. Provider input measurements do not prove active-context size; conflicting values remain gaps and runtime compaction counters stay separate.

- Raw scanning uses UTF-8 byte offsets, physical LF/CRLF delimiters, and SHA-256 record hashes. An unterminated tail remains pending.
- Normalization is capped at 8 MiB per record; larger records keep raw byte references and range access.
- One selected in-memory index retains at most 100,000 record references, 3,000 evidence items, and 20,000 call groups. Deliberate limits remain visible in coverage.
- The timeline retains at most 40,000 events, renders at most 120 overview groups and 50 events per range, and exposes omitted captures. Captured reasoning is shown only where recorded; missing reasoning is not proof that none occurred.
- Usage details return 20 response groups per page. Matching repeated measurements count once; conflicting or unassigned groups stay outside resolved subtotals. Claude input includes uncached input plus cache read and creation only when all required fields are known; Codex cache read is part of reported input.
- Source views return up to 32 KiB at a time after validating the entire referenced record. Large-record access can therefore take time.
- The collapsed **Recorded context windows** panel pages at most 50 evidence rows, retains at most 1,000 windows and 1,000 separate summary/representation records, and caps captured metadata at 4 MiB. List previews show at most 20 entries and displayed IDs/values at most 512 bytes. Intervals follow recorded physical source order from the first retained complete record or a recorded compaction boundary to the next same-scope boundary, or the last retained complete source record. They do not establish conversation start, active model-context membership, a request, or the before/after meaning of native window numbers. Unknown ownership, unlinked or ambiguous summaries, and capture omissions remain visible.
- The source list reads file stats only, with a four-second/20,000-file budget. A partial list states its limits; ordering is recent within inspected candidates.
- T3 lists up to 50 current non-deleted threads per live page, including archived threads. Titles/project names and workspace paths use 512/2,048-character display prefixes. Catalog pages can change while T3 runs.
- Current links use the active provider-thread's payload_json.nativeThreadRef.nativeId only after its provider, driver, provider instance, owning T3 thread, and matching provider-session binding agree. The default provider is a preference when no active binding exists. Native UUIDs are corroborated against Codex/Claude JSONL identity fields; opaque T3 provider-thread and provider-session IDs are not parsed as provider IDs. Unsupported providers or native-ID formats retain catalog metadata without an inferred recording link.
- Log discovery examines filenames containing that provider ID inside allowed roots (four seconds, 20,000 entries, 100 candidates), then corroborates the ID within 512 KiB / 64 complete prefix records. Filename, time, project, and equal text alone do not verify a link. Incomplete or multiple matches require an explicit recording choice.
- No matching candidate means recording not located within that coverage. It does not prove absence elsewhere. Missing active provider-thread/session-binding references and unknown providers remain separate states. Historical provider switches, replaced bindings, and child actors are not recovered by the current active binding.
- Selected T3 metadata is bounded to 24 KiB of cell values / 32 KiB of serialized evidence per row; references are memory-only, capped at 200 and expire after ten minutes. No T3 content is added to provider injections, usage totals, or reconstructed requests.
- Reopening a session rebuilds the index. Missing/stale evidence produces an error instead of replacing historical content with current instructions.
- No automated test suite is included.

Code lives in src/core (byte/source/evidence contracts), src/adapters (provider formats), src/server (local read service), and src/ui (React).
